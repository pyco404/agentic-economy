# Agentic Economy — Claude Code Backend Implementation Brief

**Official project:** Agentic Economy

## Non-negotiable product decisions

- Launchpad uses Pump.fun only; communities are ONLY tokens launched through our own platform flow. No external-token imports.
- Every wallet may launch unlimited tokens; no wallet rate limits, cooldowns, creator history checks, duplicate metadata gates or manual approvals.
- Flat launch fee: 0.05 SOL per successful launch, entirely for platform treasury; this is distinct from creator-fee revenue.
- Launcher receives 0% of eligible creator-fee allocation. Of creator fees actually routed to our system, 60% belongs to agent reward treasury and 40% to platform treasury, only where supported by current Pump.fun mechanics. Do not claim we can redirect Pump.fun protocol or LP fees.
- Agent rewards require verified useful services, bounded funds and anti-abuse checks, NOT passive token holding or trading-volume bonuses. MVP rewards are dry-run/points only.
- One shared, persistent and expandable world. Agent professions are individual, not assigned to entire token communities.
- Structures, roads, trees, terrain, water and city expansion are procedurally generated by code in an original minimalist isometric architectural style inspired by the reference screenshot.
- $AECO launches after the product is ready; no token mint, buyback, burn or real agent reward payouts in MVP.

## First assignment — contracts, simulation and integration foundations

1. Inspect repository and master spec; preserve existing work. Establish pnpm workspace / TypeScript strict mode as appropriate, shared Zod API/event schemas, OpenAPI contract and seeded fixtures.
2. Implement wallet challenge/signature verification with anti-replay sessions; immutable community registration restricted to verified launches through our platform. Holder eligibility based on trusted chain data, not browser claims.
3. Model persistent world chunks and seeded structure configs; simulation authority stays server-side. Publish minimal world/agent/building APIs and WebSocket update messages. Make multiple clients see the same world seed and building placement.
4. Implement deterministic production loop (wheat → flour → bread), inventories, City Credits (non-withdrawable), maintenance, economic tasks, task verification receipts and an agent decision policy with bounded permissions. Agents cannot sign user wallet transactions.
5. Model token launch state machine, fixed 0.05 SOL platform fee collection, on-chain confirmation and idempotent recovery/failure handling. Do not impose launch frequency limits.
6. **Research actual current official Pump.fun mechanisms before implementing routing.** Establish whether creator fee recipient/share allocations, 0% launcher entitlement and continuation after PumpSwap graduation are supported. Document exact supported operations, addresses, trust boundaries and limitations. Never treat platform fee, creator fee, Pump.fun protocol fee and LP fee as interchangeable.
7. Use append-only treasury receipts and double-entry or equivalently reconciliable accounting; 60/40 applies solely to creator fees *received* and eligible for split. Track chain signatures, mint, quote asset, decimals, pending/confirmed/reversed events and duplicate-safe postings. Keep launch-fee proceeds in platform-only accounting.
8. Design **dry-run** verified-service agent reward queue with earned work records, task validity, caps, disputes and no mainnet payouts. Document separated real-money payout controls before implementing any live payment.
9. Database migrations, event replay/restart recovery, integration tests for duplicate/failure paths, docs and operational metrics.

## Acceptance criteria

- World state persists and survives restarts; simulation is deterministic given inputs.
- Wheat→flour→bread full loop completes without negative inventory or uncontrolled money creation.
- Wallet auth challenge cannot be replayed; launch confirmation is idempotent.
- 0.05 SOL fee path is separated from Pump.fun creator-fee income.
- No arbitrary restrictions on number of token launches per wallet.
- 60/40 treasury ledger reconciles, or unsupported Pump.fun routing is explicitly documented as a blocker and financial features remain disabled.
- Verified tasks are traceable; fake actions or mere token ownership do not earn redeemable rewards.
- Backend builds, typechecks and tests locally; no unchecked mainnet payouts or automatic $AECO token operations.
